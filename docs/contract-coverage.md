## Forward migration 029

The API writes manual charges and their financial snapshots in one transaction.
Previously the database allowed the two records to disagree about money, concept,
justification, actor, timestamp, type or procedure. The new insert trigger checks
these fields and the Clinical source quantity/type without changing API payloads
or granting runtime extra privileges. Decimal values compare numerically, allowing
equivalent representations such as `10.0` and `10.00`.

The payment receipt now references the composite payment/invoice identity. An
otherwise valid event and snapshot for another invoice cannot be attached to that
payment. This foreign key validates existing receipts during migration; inconsistent
history stops deployment and requires owner investigation, never automatic deletion.
The manual insert trigger protects future inserts; it does not rewrite historical data.

Regression: `tests/financial-correlations.sql` exercises eight mismatched manual
fields, a valid API-shaped manual write and a receipt belonging to another invoice.
Run it with every existing SQL suite using `python tests/run-isolated.py`.

Verified locally on 2026-11-07 with PostgreSQL 16 and Liquibase 4.31.1:
changelog validation, initial update, repeat update with unchanged history and all
11 SQL suites passed, including the new correlation regression. The disposable
container and network were removed after the run. No existing database was modified.

## Deployment and acceptance boundaries

- Provision `deploy/bootstrap.sql` as DBA, migrate with `billing_migrator`, run the
  API with `billing_runtime`; see `runtime-permissions.md`.
- Migration 030 seeds the six documented MVP payment codes as active when missing;
  existing owner activation choices are preserved. See `payments.md` for codes and
  configuration. The HTTP/Portal accepts a method string and the API checks this
  table. No real gateway is configured here.
- IAM session/role and current care authorization, Appointment finalization and
  HTTP replay authorization belong to the API and contractual owner calls.
- No permanent PDF table or direct foreign keys to other owner databases are needed.
- Real IAM/Gateway/browser acceptance, deployment and backup/restore verification
  require their own environment evidence. Retention policy and temporal catalog
  selection remain documentation decisions; this change invents neither.
